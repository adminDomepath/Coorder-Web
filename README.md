# Coorder website

Official public website for Coorder at `coorder.domepath.com`.

The site introduces the Coorder app and its Clover integration, provides the
required Clover App Market Privacy Policy and EULA, and uses the same visual
language as the SwiftUI application.

## Local development

```bash
npm install
npm run dev
```

## Validation

```bash
npm test
```

## GitHub Pages

Pushes to `main` automatically build and deploy the static site to
`https://coorder.domepath.com/`.

## DoorDash restaurant portal

- Entry: `https://coorder.domepath.com/connect/doordash/`
- Public help: `https://coorder.domepath.com/connect/doordash/help/`
- API: Firebase `doorDashPortal` in `domepath-coorder`, `us-west1`.

The portal uses a single-use, ten-minute access code generated by the signed-in
Coorder app (`Settings → DoorDash`). Browser sessions last one hour and are
stored in sessionStorage, scoped to DoorDash connection management. DoorDash
merchant tokens remain on the backend. This does not add a new web login
provider or use Sign in with ChatGPT for restaurant identity.

The current rollout supports existing DoorDash restaurants in Sandbox. OAuth
is disabled until the DoorDash Client ID, Marketplace access key, onboarding
status webhook, and redirect approval are configured. The portal shows the
pending state without claiming that a restaurant is connected. New restaurant
signup and production certification are outside this rollout.

See the sibling Coorder repository's `Documentation/DoorDashPortal.md` for
backend setup and deployment. The app build containing the new Settings screen
must be installed before a merchant can generate an access code.
